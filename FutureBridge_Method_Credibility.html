The method is not new. What is new is that the landscape is mapped before the news arrives.

Discovery-driven planning, causal modelling, and driver-based planning are each well established. FutureBridge did not invent them. We connect them — and we populate the full landscape of hypotheses in advance. When a story breaks, we already know where it lands.

Most approaches describe the future. This one tests whether it is arriving, and reads the impact of each event off a map that already exists.

01The shift

The landscape comes first

Strategy questions do not arrive one at a time. A single market holds dozens of open questions at once. Will local manufacture beat import. Will demand tip toward electric. Will a domestic supplier base form in time.

We write each as a falsifiable claim, with a threshold, and we map how they connect. That map is the landscape. It exists before any particular news story does.

When an event arrives, the work is not to analyse it from scratch. It is to locate it. Which hypotheses does it touch. Which thresholds does it move. What does it set off downstream. Because the structure is already built, the answer is immediate.

This is the difference. A story that looks minor in isolation can move three thresholds at once. You only see that if the landscape is already drawn.

Three established disciplines, wired together

Each pillar exists on its own across strategy practice. The connection is the part that does not.

Pillar 01
What must be true

Discovery-driven planning

Rita McGrath · Ian MacMillan. Harvard Business Review, 1995. Foundational in corporate venture strategy and new-market entry.

Strategy for uncertain markets should start with explicit assumptions about what must be true — not treat them as fact. Making them visible allows deliberate testing.

FutureBridge application

We write those assumptions as measurable thresholds. WNTBT — what needs to be true — with specific numbers, not narratives. Each one is a claim the evidence either supports or breaks.

Pillar 02
How the system works

System dynamics

Jay W. Forrester · MIT Sloan. Originated system-dynamics modelling. The basis for much of modern supply-chain and policy simulation.

Complex outcomes come from interconnected variables and feedback loops, not single causes. To understand a system you map its causal structure. A change in one node moves the rest.

FutureBridge application

We map the causal structure of each question — regulation, technology cost, supply chain, competition — so we know which variables actually drive the outcome, and in what order.

Pillar 03
What moves the outcome

Driver trees

McKinsey-style driver-tree planning. Widely adopted in CFO and FP&A practice. Decomposes performance into measurable input variables.

Performance is driven by a small set of measurable inputs. You manage a business by tracking those inputs, not the financial outputs. The right drivers give early warning.

FutureBridge application

We track the input nodes that move the outcome — tariff rates, local content, cell costs, regulatory milestones. Each news event is classified by which node it moves, and by how much.

The connection

The components are standard. The connection is not.

Each discipline above usually sits in isolation. Discovery-driven planning rarely connects to a real causal model. Driver trees rarely connect to external signal classification. And none of them update in real time.

We connect all three. Then we add a fourth layer: live news, classified against the model, updating the thresholds continuously rather than at the next review.

The landscape is populated and live. A tariff vote, a cost milestone, a regulatory decision — each is located on the map the day it lands. The relevant threshold moves. The decision window opens or closes. That cycle runs continuously, not annually.

From evidence to decision

Five steps. The first four exist before the news does.

01

Build the landscape

Many falsifiable hypotheses across the whole question, not one at a time. Each is a claim that can be proven wrong, tied to the decision it informs.

02

Set the thresholds

The WNTBT conditions, with numbers, that must hold for each hypothesis to stand. Measurable claims, not narrative assumptions.

03

Map the causal drivers

The input variables that decide whether each threshold is met — cost, regulatory timing, supply-chain depth, market dynamics. Mapped as a connected system, not a list.

04

Classify the live signal

Each story is classified by which node it moves and in which direction. Only events that touch a threshold become signals. Everything else is noise.

The news arrives. Steps one to four are already built. Everything below happens the day the story lands.
05

Read the impact, open the window

One event, located on the map, shows every threshold it touches and what it sets off downstream. Where thresholds converge, the decision window opens. The system surfaces it directly.

↳A worked example

One announcement. Three thresholds moved.

A global automaker was weighing local manufacture against import in a large, fast-growing market. The landscape held several open hypotheses at once: whether local production could beat imports on cost, whether demand would tip toward electric, whether a domestic supplier base would form in time, whether a trade agreement would reshape tariffs.

Each carried a threshold. The cost question turned on a crossover — the tariff level at which importing finished vehicles becomes cheaper than building them locally. We modelled that crossover and stress-tested it. A modest swing in local manufacturing cost moved the crossover point by several points of tariff.

Then a single event arrived. A trade agreement cut import tariffs in phases. In isolation, a line in a policy document.

Located on the landscape, it touched three hypotheses at once.

It pushed the build-versus-import calculation toward import. It changed the payback on a local plant. And it shifted the timing of the electric-demand question, because cheaper imports change the model mix on sale. The decision window on the plant investment narrowed — visibly, the day the news landed, not at the next strategy review.

Modelled tariff crossover
As import tariffs rise, imported vehicles get dearer while local build cost holds. Where the lines cross, the cheaper option flips. A swing in local cost moves that crossover to roughly 32–44%.

A fair question

"Is this a new framework?"

The honest answer is no. It is built on McGrath's discovery-driven planning, Forrester's system dynamics, and McKinsey-style driver trees. None of it is proprietary.

What is different is connecting them into a live, populated landscape that updates with external signals and makes the decision window explicit. Claiming a proprietary method invites scepticism. Naming the foundations does the opposite.

The landscape is drawn before the news arrives. That is the whole point.
External events → driver nodes → thresholds → decision window.
That cycle runs continuously. Strategy reviews run annually.
The difference is not sophistication. It is speed.
