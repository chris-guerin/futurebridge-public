FutureBridge Signal Engine · The method · May 2026

The method is not new. What is new is that the landscape is mapped before the news arrives.

Discovery-driven planning, causal modelling, and driver-based planning are each well established. FutureBridge did not invent them. We connect them — and we populate the full landscape of hypotheses in advance. When a story breaks, we already know where it lands.

Most approaches describe the future. This one tests whether it is arriving, and reads the impact of each event off a map that already exists.

01The shift

The landscape comes first

Strategy questions do not arrive one at a time. A single market holds dozens at once — will local manufacture beat import, will demand tip toward electric, will a supplier base form in time. We write each as a falsifiable claim with a threshold, and map how they connect.

So when an event arrives, the work is not to analyse it. It is to locate it. The structure is already built, so the answer is immediate.

A story that looks minor in isolation can move three thresholds at once. You only see that if the landscape is already drawn.

Three established disciplines, wired together

Each pillar exists on its own across strategy practice. The connection is the part that does not.

Pillar 01
What must be true

Discovery-driven planning

Rita McGrath · Ian MacMillan. Harvard Business Review, 1995. Foundational in corporate venture strategy and new-market entry.

Strategy for uncertain markets should start with explicit assumptions about what must be true — not treat them as fact. Making them visible allows deliberate testing.

FutureBridge application

We write those assumptions as measurable thresholds. WNTBT — what needs to be true — with specific numbers, not narratives. Each one is a claim the evidence either supports or breaks.

Pillar 02
How the system works

System dynamics

Jay W. Forrester · MIT Sloan. Originated system-dynamics modelling. The basis for much of modern supply-chain and policy simulation.

Complex outcomes come from interconnected variables and feedback loops, not single causes. To understand a system you map its causal structure. A change in one node moves the rest.

FutureBridge application

We map the causal structure of each question — regulation, technology cost, supply chain, competition — so we know which variables actually drive the outcome, and in what order.

Pillar 03
What moves the outcome

Driver trees

McKinsey-style driver-tree planning. Widely adopted in CFO and FP&A practice. Decomposes performance into measurable input variables.

Performance is driven by a small set of measurable inputs. You manage a business by tracking those inputs, not the financial outputs. The right drivers give early warning.

FutureBridge application

We track the input nodes that move the outcome — tariff rates, local content, cell costs, regulatory milestones. Each news event is classified by which node it moves, and by how much.

The connection

The components are standard. The connection is not.

Each discipline above usually sits in isolation. Discovery-driven planning rarely connects to a real causal model. Driver trees rarely connect to external signal classification. And none of them update in real time.

We connect all three, then add a fourth layer: live news, classified against the model. A tariff vote, a cost milestone, a regulatory decision — each located on the map the day it lands. The relevant threshold moves. The decision window opens or closes.

That cycle runs continuously. Strategy reviews run annually.

A fair question

"Is this a new framework?"

The honest answer is no. It is built on McGrath's discovery-driven planning, Forrester's system dynamics, and McKinsey-style driver trees. None of it is proprietary.

What is different is connecting them into a live, populated landscape that updates with external signals and makes the decision window explicit. Claiming a proprietary method invites scepticism. Naming the foundations does the opposite.

The landscape is drawn before the news arrives. That is the whole point.
External events → driver nodes → thresholds → decision window.
That cycle runs continuously. Strategy reviews run annually.
The difference is not sophistication. It is speed.
